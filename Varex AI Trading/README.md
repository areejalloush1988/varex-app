# VAREX AI Trading

واجهة تداول عربية مستقلة تستخدم Supabase Auth للحسابات وخدمة `varex-trading-api` لحفظ البيانات والتحليل وإجراءات التداول. يحافظ `trading/index.html` على التصميم نفسه ويعرض التطبيق مباشرةً دون iframe.

## روابط التطبيق

- الرابط الرسمي في بيانات الصفحة: `https://app.varexapp.com/trading/`.
- نسخة GitHub Pages: `https://areejalloush1988.github.io/varex-app/trading/`.
- النطاق المخصص مرتبط باستضافة VAREX المركزية؛ تحديث GitHub أو وسم canonical وحده لا يحدّث تلك الاستضافة ولا يغير DNS.

## الوظائف

- تسجيل الدخول وإنشاء الحساب وتأكيد البريد برمز من ستة أرقام، وإعادة الإرسال واستعادة كلمة المرور.
- حفظ الجلسة اختيارياً وتجديدها، وإلغاؤها عند تسجيل الخروج.
- ملف ورصيد ورقي وصفقات وتحليلات وقائمة مراقبة وتفضيلات مستقلة لكل مستخدم في Postgres.
- أسعار وشموع من Coinbase للأسواق BTC-USD وETH-USD وSOL-USD وADA-USD، وتحليل فني احتمالي محسوب من بياناتها.
- فتح وإغلاق صفقات ورقية بسعر يجلبه الخادم، مع حدود الحجم والخسارة اليومية وعدد المراكز المفتوحة.
- تحديث السوق كل 30 ثانية بعد انتهاء الطلب السابق أثناء تسجيل الدخول وظهور التبويب.
- إغلاق المراكز الورقية عند بلوغ الوقف خلال تحديث الأسعار. تتوقف المتابعة عند إغلاق التطبيق؛ لا توجد مهمة خلفية مستقلة.
- حفظ مسودات النماذج أثناء التحديث، ونقل رمز التحليل واتجاهه إلى التذكرة الورقية، وتصدير CSV.
- فصل حفظ صلاحية المستخدم عن تفعيله أو إيقافه. الإدارة مرتبطة بالبريد الأساسي المؤكد `areejalloush1988@gmail.com`.
- حساب حدود اليوم عند 00:00 UTC، مع الاحتفاظ بكل المراكز المفتوحة وإغلاقات اليوم و500 صفقة مغلقة أقدم.

## التداول الحقيقي

الوسيط المدعوم هو **Binance Spot**. يحتاج كل مستخدم إلى ربط حسابه بمفتاح يسمح بالقراءة وSpot Trading فقط. تُرفض صلاحيات السحب ونقل الأموال وMargin وFutures وOptions. التنفيذ الحقيقي متوقف افتراضياً ويتطلب تفعيله من الحساب ثم تأكيد كل أمر يدوياً.

يُشفّر المفتاح والسر قبل الحفظ ولا يُعادان إلى الواجهة. يُحجز معرّف الأمر في قاعدة البيانات قبل الاتصال بالوسيط؛ ولا يعاد إرساله عند انقطاع الاتصال أو غموض النتيجة. الأموال والإيداع والسحب تبقى لدى الوسيط.

هذه النسخة لا تتضمن وسيط فوركس أو ذهب أو نفط، ولا بوتاً يقرر الصفقات تلقائياً. اختبار الاتصال أو تنفيذ أمر حقيقي يتطلب بيانات المستخدم وموافقته على الأمر داخل التطبيق. التحليل احتمالي وليس ضماناً للربح.

## البنية والنشر

- `index.html`, `styles.css`, `app.js`: الواجهة وأوامرها.
- `supabase-api.js`: تحويل الطلبات إلى Supabase Auth وEdge Function. يحتوي المفتاح العام فقط، دون مفاتيح خادم أو وسيط.
- `../trading/index.html`: مدخل المسار العام، يستعمل الأصول نفسها.
- `../supabase/functions/varex-trading-api/`: الخدمة ومكتبتا السوق والوسيط والاعتماديات المثبتة.
- `../supabase/migrations/20261030053731_varex_trading_standalone.sql`: جداول التداول الخمسة وإجراءاتها الذرية.
- `../supabase/templates/varex-recovery-email.html`: قالب الاسترداد الذي يتضمن الرمز ورابط الاسترداد الأصلي.
- `backend/`: نسخة التكامل السابقة مع D1 ونظام VAREX المركزي، محفوظة للمرجع. لم تُنقل منها سجلات قديمة إلى جداول Supabase الجديدة.

تتحقق الخدمة من المستخدم والبريد المؤكد وحالة الحساب وصلاحياته. جميع البيانات محصورة بمعرّف المستخدم المتحقق منه. تفعيل RLS وسحب صلاحيات المتصفح يمنعان تعديل الرصيد والأدوار والأوامر عبر Data API مباشرة. تخزين الحالة وإصدارها والرصيد يتم بمعاملة واحدة.

يلزم سر `TRADING_CREDENTIAL_KEY` لحماية بيانات الوسيط. تُقبل مفاتيح Base64 من 32 بايت كما هي، ويُشتق AES-256 من الأسرار العشوائية ذات 48 بايت باستخدام SHA-256 وبادئة خاصة بالتطبيق. تغيير السر بعد ربط حسابات يحتاج خطة لإعادة تشفير البيانات.

يسمح CORS بالنطاق الرسمي وGitHub Pages المحددين في الخدمة. يرسل المتصفح Bearer JWT للمستخدم؛ المفتاح العام وحده لا يمنح الوصول إلى بيانات التداول. التحقق من المستخدم داخل الخدمة إلزامي، ويجب توافق إعداد بوابة JWT مع مفاتيح توقيع المشروع.

## الفحوص

من هذا المجلد باستخدام Node.js 24 أو أحدث:

```bash
npm ci
npm test
```

تشمل الفحوص عناصر التحكم والمصادقة وتجديد الجلسات، وعزل الحسابات والصلاحيات، وتشغيل SQL في PostgreSQL داخل الذاكرة، وCAS والتراجع عند الفشل، ووقف الصفقات الورقية ومنع تكرار أوامر الوسيط. جميع اتصالات الوسيط والبريد في الاختبارات محاكاة؛ لا تُرسل صفقات أو رسائل فعلية.
